# A Song's Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** History gets a *Songs* view beside *Rehearsals*. Every song has a page: a ladder of its goes, one rung per rehearsal. Any song title the app shows opens that page, and reha.stream gets a fifth story step that shows it.

**Architecture:**
- Python:
  - `Library.songs()` and `Library.goes_of(song_id)` read the store.
  - `Api.list_songs()` and `Api.get_song(song_id)` hand them over, `get_song` adding what ▶ plays.
  - History's view is one more key in `config.json`.
- Interface:
  - History holds every take as a `PlacedTake` (the take plus its rehearsal's folder), so goes from several rehearsals share one player and one set of dialogs.
  - The Songs view is three new components (`HistorySwitch`, `SongList`, `SongPage`) and the ladder (`SongLadder`), built from the overview's own `TakeRow`.
- The fake bridge, the band and the site each learn the two new calls.

**Tech Stack:** Python 3.12, SQLAlchemy 2 + Alembic on SQLite, pywebview; React 19 + TypeScript + Tailwind, lucide-react icons; Vitest; Playwright against `ui/e2e/fake-bridge.js`; the site in `site/` (Vite, Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-02-song-page-design.md`. Variant B of [the mockup](https://claude.ai/artifact/NnE5oTiWEPqMcX3L72HPYq) is what the page looks like; its source is the copy for every string this plan does not give.

## Global Constraints

- No new dependencies: `requirements.txt`, `ui/package.json` and `site/package.json` stay as they are.
- No migration. Everything is read from the columns there are.
- History's view is kept in `config.json` under `history_view`:
  - it is `"rehearsals"` or `"songs"`;
  - missing or anything else reads as `"rehearsals"`;
  - never in `localStorage` (spec H1).
- Songs are in alphabetical order: `new Intl.Collator(undefined, { sensitivity: "base" })`, the one `SongPills.tsx` uses (spec D2). *Not named* is always last (H3).
- A song's goes: newest rehearsal first; within one, the order played (D3).
- A rehearsal not on disk (D5):
  - its goes are listed and counted, greyed, and say *Not found on disk*;
  - they have no ▶ and do not open;
  - ▶ on the head passes over them.
- A song with no goes left is not listed.
- What a song's ▶ plays is its newest ★ go on disk, or with none its last go at its newest rehearsal on disk.
  - "Newest" is the rehearsal's `created_at`, then the later take in the evening, never the go number (stars, D4).
  - With nothing on disk it plays nothing.
- What does **not** open a song's page:
  - the song pills and the All songs panel under the name field (O1);
  - the rehearsal screen, which does not open History (O3);
  - the site's tiles (`site/src/page/pieces.tsx`, which shows `RehearsalOverview`).
- Copy is English, as the app is.
- Test titles, and `ok()` labels, stay in Latin script: Windows CI cannot print Cyrillic. Data in tests can be any script.
- Python tests are scripts, not pytest. Each check is `ok(label, cond)` inside `main()`, under `print("\n[N] …")` headings.
  - Run: `venv/bin/python tests/test_engine.py`.

- Full suites run once, at the end (Task 9): `venv/bin/python tests/run_all.py`, `cd ui && npm run build && npm run test:e2e`, the site's both.

## Decisions made while planning

These fill gaps the spec and the mockup leave open. Each can be changed before the code is written.

1. **History starts on the first row of the Songs list** when no song was asked for, as the Rehearsals view starts on its first row.
2. ***Not named*'s page** follows the mockup:
   - its head has no ▶, no *Starred* and no *From last time*;
   - under its title: "Takes nobody named. Rename one to give it a song."
3. **A go not on disk** keeps its bar, name, length and mark ticks. It loses ▶, every action (★, Rename, cloud, Delete) and its note lines, as in the mockup. Python cannot change a take whose folder it cannot reach.
4. **The *Not named* heading** in a rehearsal's overview, and Last time's *Not named* row, do not open a page. O1 names song titles only.
5. **Switching views** keeps a take playing in the overview playing. Choosing another song stops it, as choosing another rehearsal does today.
6. **Dates in the Songs view** read "22 Sep" within the current year, and "22 Sep 2025" before it. A band's history runs past New Year.
7. **The band's past goes are numbered across its library**, as Python numbers them. The demo then shows no two "Pałyn 2" on one song page.
   - This changes go numbers in the band's 22 Sep and 19 Sep rehearsals, which the History screenshot and the site show.
   - The live session (`EARLIER`: Pałyn, Pałyn 2, Viasna) is untouched: the hero, `band.spec.ts` and the player screenshot keep "Pałyn 2".
8. **The site's new step** (Alex chose a fifth step on 2026-10-06):
   - id `song`;
   - caption: *Find a song.* "Every go at it, from every rehearsal, one line an evening. ▶ plays the ★ one."
   - the stage switches History to *Songs* and opens Pałyn.
   - The site's demo never saves the view: going back a step must find History on *Rehearsals* again.

## Review Focus

The five failure modes most likely to bite, each pinned by a test in the task named:

1. **Two rehearsals both have a take 2.** One playing in the overview must not count as the other:
   - ▶ on the other starts it and does not pause the first;
   - the overview of the other rehearsal does not show it playing (Task 3, Task 5).
2. **The only go of a song is deleted, or renamed to another song, from the song's page.** The song leaves the list, and the page moves to its neighbour instead of showing an empty or stale page (Task 5).
3. **The newest rehearsal of a song is not on disk.**
   - The rung open at first is the newest one on disk.
   - ▶ plays from a rehearsal on disk.
   - *From last time* is that rehearsal's (Task 1, Task 3).
4. **Python does not answer the saved view at once.** History must not flash *Rehearsals* and then jump to *Songs*; it shows the list only once the view is known (Task 4).
5. **Titles in either case, and in two scripts.** "opus" respelled "Opus" is one song in Python. The list sorts "bridge jam" before "Daroha", case-blind, and Cyrillic titles after Latin ones, not by code point (Task 1, Task 3, Task 4).

  export type SongSummary = { id: number; title: string; goes: number; rehearsals: number;
    first_played: string; last_played: string; starred: number }
  export type NotNamedSummary = { takes: number; rehearsals: number; last_played: string }

  - `type SongRef = number | "not_named"`.

# Song sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sets of songs picked beside Start rehearsal and gone through on the rehearsal screen with a list and ↑ ↓ in place of the pills, kept in History; *Before tonight* removed; the screen after a take reduced to the song, its goes and its length; reha.stream and the docs told.

**Architecture:** Sets live in the library database (migration 0006) and are copied onto a rehearsal when it starts. Python answers sets as it answers labels (whole list back on each change). The interface gets one component file for the rows (set card and song list), one for editing a set (start-screen window and Settings), and changes to the start, rehearsal, review, Settings and History screens. The mockup on the local branch `mockup/step8` (never pushed) has working prototypes of each piece (`ui/src/components/Mk*.tsx`); they are a reference for markup and classes only, not code to copy: every piece here is written test first.

**Tech Stack:** Python 3.13, SQLAlchemy + Alembic on SQLite; React 19 + TypeScript + Tailwind in `ui/`; Playwright on the fake bridge; Vite site in `site/`.

**Spec:** `docs/superpowers/specs/2026-10-08-song-sets-design.md`

## Global Constraints

- Python check labels and Playwright test titles are Latin only (Windows CI prints cp1252): "Polyn", not "Pałyn"; no ★, no ✓ in titles.
- Set names: trimmed, at most 40 characters (as `LABEL_NAME_MAX`), unique compared by `casefold()`.
- Set songs: titles, each trimmed, empty ones dropped, a repeat kept once at its first place (casefold).
- Migration is 0006; the band-chat spec's 0006 becomes 0007.
- `config.json` key `next_set` holds a set id or null.
- Five rows show in the other-songs list; *All N songs* appears only with more than six (spec R5).
- Copy, exact: "No set", "No set: play freely", "New set…", "N songs" / "1 song", "Other songs", "Songs", "All N songs", "Fewer", "next", "N goes" / "1 go", "N of M played", "No song has “x” in it. The take makes it a new one.", "Rehearse the set, in order.", tile text and story lines as the spec gives them.
- No layout jumps: the list's height is held while the field is typed in; the set card never changes height during an evening.
- Commits end with the two attribution lines the session gives; no model names in the repo.

## Review Focus

- A set whose song was renamed or merged after the set was made: rows, ✓ and *next* must use the current title (D8).
- A set song never played (new song): its row must name the next take after the typed title, and its first take must make the song.
- The arrow keys while a dialog is open over the rehearsal screen (Rename take, Delete) or while a take is open must not move the next take.
- The review screen after a crop (Review re-renders with a new `take`): the title, bars and line must keep the renamed name.
- A deleted set chosen as `next_set`: the start button must say *No set* and starting must not send the stale id.

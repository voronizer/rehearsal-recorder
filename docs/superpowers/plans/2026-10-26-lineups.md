# Named lineups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The band keeps several named lineups, picked from a menu that is the title of the setup screen's tracks, and every take keeps the icons it was recorded with.

**Architecture:** Lineups live in `config.json` beside last time (`tracks`, `layouts`), each the same shape, so `layouts.for_device` and `layouts.remember` work on them unchanged. Python lays every lineup out on the card in force and the screen works out *changed* itself. A take's icon moves from a lookup in the band to a column of `take_file` (migration 0010).

**Tech Stack:** Python 3 (pywebview bridge, SQLAlchemy, Alembic), React + TypeScript + Tailwind (ui/), Vite site (site/), Playwright, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-lineups-design.md` (ок'd by Alex 2026-10-26 08:24Z). Read it first; this plan does not repeat its reasons.

## Global Constraints

- User-facing words in English, British spelling, sentence-case buttons (F7), a name in a title in curly quotes: *Delete “Trio”?* (B8). Prose rules: `CLAUDE.md` › Writing.
- Exact words on screen: `Full band · changed`, `Tracks` (no lineup picked), **Update**, **Save as new…**, menu items **Save as new lineup…**, **Rename “X”…**, **Delete “X”…**, `4 tracks`; dialog *Save as a new lineup* / *The tracks on screen, their icons and their inputs.* / **Name** / **Save lineup**; *Rename “X”* / **Rename**; *Delete “X”?* / *The tracks on screen stay as they are. Rehearsals recorded with it keep their tracks.* / **Delete lineup**; errors *A lineup needs a name* and *There is already a lineup called X*; notice *Your changes to X were not kept.* with **Undo**.
- The migrated lineup is called `Band`.
- Lineup names: trimmed, cut to `LABEL_NAME_MAX` (40, `store/library.py:34`), refused empty or taken by casefold.
- Migration number `0010`, revises `0009`.
- Python and browser test labels: cp1252 characters only (Latin, no ★ ▶ ▾ “ ”).
- While building, run only the tests a change touches, once each. The full suites run on CI.
- Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`; no `Claude-Session:` line.

## Review Focus

1. **A config edited by hand**: `lineups` that is not a list, an entry without a string `name`, or `lineup` naming nothing. The app opens, bad entries are dropped, `lineup` becomes null. (Task 1, test "a hand-edited lineups key".)
2. **No interface in hand** (the saved card unplugged): load, pick, Update and Save as new work against no card, as `remember` already keeps a map for no card. (Task 1, test "Update with no card".)
3. **A lineup bigger than the card**: on a two-input box Full band's later tracks arrive with no input. The screen is not *changed* for that alone, and Start stays blocked as today. (Task 3, test "a lineup bigger than the card is not changed".)
4. **Renaming to the same name in another case** (`trio` → `Trio`) is allowed; to another lineup's name in any case it is refused. (Task 1.)
5. **A take whose track the band never had** gets no `icon` key at all (not `""`), and the neutral icon. (Task 2, backfill test.)

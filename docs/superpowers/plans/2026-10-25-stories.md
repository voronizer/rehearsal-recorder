# Stories on reha.stream: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** reha.stream gets four stories at `/stories/<name>`, a page of them at `/stories`, **Stories** in the menu, and the band's chat in a block right after the main page's first screen.

**Architecture:** The stories are Markdown in `site/content/stories/`, read by a parser of their own (`src/content/stories.ts`) into chapters, paragraphs, jokes and chats. At build time a Vite plugin bundles `src/stories/render.tsx` for Node, renders each page with the site's own React components to static HTML, and writes it into the built template `stories.html`, with its title, description, canonical address and `Article`. On the page only a small script runs: Vercel's counting and the visitor's system first in the downloads. The main page's block is a client component like the rest of the main page.

**Tech Stack:** Vite 8, React (the interface's, `react-dom/server` at build time), Tailwind 4 via `page.css`, Vitest, Playwright, Vercel legacy `routes`.

**Spec:** `/mnt/project-files/reha-stream/stories/spec.md` (ok'd by Alex 2026-10-25 19:01Z; the block's place changed by his card at 19:06Z). Approved mockup sources: `/mnt/project-files/reha-stream/stories/mockup-src/` (`tale.tsx`, `mock.css` for the story page; `nav.tsx`, `nav.css` for the menu, the page of stories and the chat block, option 1).

## Global Constraints

- Words from the spec verbatim: titles, descriptions, the block's heading, line and link, the page of stories' heading and line, the byline.
- The story texts are the approved files in `/mnt/project-files/strategy/guides/`, word for word, minus the byline line and the download line.
- English, British spelling. Curly double quotes “ ”, straight apostrophes, in the content files and the CHANGELOG.
- No new npm packages: `react-dom/server` comes from `ui/node_modules` through the existing alias.
- Every page of the site has the menu How it works, FAQ, Stories, GitHub, Download, in that order.
- Addresses with no `.html`; the canonical address has no slash at the end.
- Test titles in Vitest and Playwright use cp1252 characters only: no Cyrillic, no `›`, no curly quotes in a title (assertions may have them).
- Site text sizes stay the site's: 0.75, 0.875, 1, 1.25 rem for text, the existing `clamp()` sizes for headings (`page.css`).
- While developing, run only the tests a change touches, once each; the full suites run once on CI.
- Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` and no `Claude-Session:` line. The PR body ends with plain “🤖 Generated with [Claude Code](https://claude.com/claude-code)”.

## Review Focus

1. **Vercel serving the new addresses.** The local preview server finds `stories/x.html` for `/stories/x` by itself; Vercel needs the routes. Expected: every story address answers 200 with its page, `/stories/` too, and `/stories/nothing` answers 404 with the site's 404 page. Unit test in Task 4; checked on the pull request's preview in Task 4.
2. **The block's chat on a short screen.** A phone on its side (844×390) never shows 40% of the stacked block at once, so lines waiting on the whole block would never come. Expected: the lines come once the chat itself is in view. Test in Task 3.
3. **Markup characters in the words** (`&`, `<`, `"`) in a description or a story. Expected: escaped in the HTML, the head and the JSON-LD. Test in Task 2.
4. **A story file saved on Windows** (CRLF, a space after the `\` of a chat line). Expected: it reads the same. Test in Task 1.
5. **The narrowest phone, 320 px.** Expected: chat bubbles, chapter names and cards wrap, and no page scrolls sideways. Tests in Tasks 2 and 3.

## Where this plan departs from the spec

- A story's address is its file's name; the top of the file has only its date and its line. Written in two places, the two could differ.
- The byline is written once, in `stories.md`, not at the top of each story.
- `/stories/` and `/stories/<name>/`, with the slash, open the page too; the canonical address has none.
- A new story needs its name in one more place, the Vercel route (Task 4), and a test fails until it is there.
- The 404 for an unknown `/stories/…` is checked by the routes' test and on the preview, not in the browser tests: the local preview server knows nothing of Vercel's routes and answers such an address with the main page.

A story file:

```markdown
---
date: 2026-10-25
description: We used to argue about which bar it was. Now we record each rehearsal from our Behringer XR18, a track per musician. How we do it, and what went wrong.
---

# Record your band's rehearsal from a digital mixer

I play bass in a band, and we never used to record our rehearsals. …

> **Guitarist:** You came in late in the second bar.\
> **Me:** No, that was the third.

## Now we record
…
```

The rules `parseStory` keeps, each failing as `site/content/stories/<file>:<line>: <what>`, with the line of the file as written (comments are blanked, not cut, so lines keep their numbers; `\r\n` reads as `\n`; trailing spaces are ignored):

| What | Error |
|---|---|
| no `---` block first, or a key in it other than `date` and `description` | `the file starts with --- and date: and description: lines` / `<key> is not date or description` |
| `date` not `YYYY-MM-DD`; either key missing or empty | `date goes 2026-10-25` / `no <key>: at the top` |
| no `# ` title right after the block; a second `# ` | `no # title after the --- block` / `one # title only` |
| `### ` or deeper | `a story has # for its title and ## for chapters, nothing deeper` |
| a line starting `- `, `* ` or `1. ` | `no lists in a story: write it as sentences` |
| a `> ` line that is not `> **Name:** words` (a trailing `\` allowed) | `a chat line goes > **Name:** what they say` |
| a name not in `WHO` | `**<Name>** is not one of Singer, Guitarist, Drummer, Me` |
| two chapters with one id | `two chapters are #<id>` |
| a `## ` chapter with nothing under it | `chapter “<title>” is empty` |

A paragraph is lines up to a blank line, joined with spaces. A paragraph that starts and ends with `**` and has no `**` inside is a joke. Lines of `> ` up to a blank line are one chat.

`readStories` fails as `site/content/stories.md: …` for: a section missing (`description`, `byline`, `order`, `block story`, `block heading`, `block line`, `block link`, via `sectionsByTitles`); a name under `order` with no file (`no stories/<name>.md`); a file not under `order` (`stories/<name>.md is not under ## order`); `block story` not under `order`; a block story with fewer than two chats in its opening. It fails as `site/content/stories/<file>: a link to /stories/<x> goes nowhere` for a link to a story that is not there, or to `#<id>` that is not a chapter of it.

The plugin, in `vite.config.ts` beside `seo()`. Vite's SSR loader cannot run React from `ui/node_modules` through the alias (it is CommonJS: “module is not defined”, tried 2026-10-25), so the render module is bundled whole for Node first, React with it (about 1.5 s):

```ts
function stories(): Plugin {
  let pages: { meta: PageMeta; body: string }[] = []
  let ssr = false
  return {
    name: "site-stories",
    apply: "build",
    configResolved: (config) => void (ssr = !!config.build.ssr),
    async buildStart() {
      if (ssr) return // the bundle below runs this config too
      const out = mkdtempSync(join(tmpdir(), "reha-stories-"))
      try {
        await build({
          configFile: fileURLToPath(import.meta.url),
          logLevel: "warn",
          ssr: { noExternal: true },
          build: { ssr: fileURLToPath(new URL("./src/stories/render.tsx", import.meta.url)), outDir: out, emptyOutDir: true, copyPublicDir: false },
        })
        pages = (await import(pathToFileURL(join(out, "render.js")).href)).storyPages()
      } finally {
        rmSync(out, { recursive: true, force: true })
      }
    },
    generateBundle: { order: "post", handler(_options, bundle) { /* below */ } },
  }
}
```

`generateBundle` (skipped when `ssr`): takes the built `stories.html` from the bundle (fails `stories.html is not in the build` if missing); for each page replaces `<!--head-->` with `pageHeadHtml(meta)` and `<!--body-->` with `body`; the page of stories replaces `stories.html`'s source, each story is emitted as `stories/<slug>.html`; fails if a placeholder is left. It emits `sitemap.xml` from `sitemapXml(["/", ...pages.map((p) => p.meta.path)])`. `seo()` keeps `robots.txt` and skips the SSR bundle too.

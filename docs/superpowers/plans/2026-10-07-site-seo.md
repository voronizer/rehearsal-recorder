# Link Picture, Search Engines and the 404 Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A link to reha.stream shows a picture in chats (the page's words beside the real rehearsal screen); search engines and AI crawlers get everything a page can tell them without running its script (Open Graph and X tags, a canonical address, JSON-LD for the app, a `<noscript>` text with the downloads, `robots.txt`, `sitemap.xml`); a wrong address on reha.stream answers 404 with the site's own page, "Nothing was recorded here", beside a silent Take 404 drawn by the app.

**Architecture:** Everything is made at build time from what the repository already holds. A small Vite plugin, `seo()` in `site/vite.config.ts`, adds the JSON-LD and the `<noscript>` text to `index.html` and writes `robots.txt` and `sitemap.xml`, all from pure functions in `site/src/content/seo.ts` (the version from `CHANGELOG.md` or the release tag, the words from `site/content/hero.md`). The link picture is a page of its own, `og.html`, drawn like the rest of the site with the real hero scene in a frame; `site/scripts/og.mjs` photographs it at 1200×630 into `dist/og.png` in CI, after the browser is installed and before the end-to-end tests. The 404 page is a third page, `404.html`, with the site's menu and footer and a silent take drawn by the app's own `SongTab` and `TakePlayer` on the fake Python side; `site/vercel-config.json` sends every address that is not a file to it with status 404.

**Tech Stack:** Vite 7 (`transformIndexHtml`, `generateBundle`, `preview()`), React, the interface's components from `ui/src`, Playwright (already used by the site's tests), Vitest, Vercel Build Output API v3 routes.

## Global Constraints

- The site's address is `https://reha.stream/`; the picture is `https://reha.stream/og.png`, absolute in every tag, 1200×630 PNG.
- `<title>` and `<meta name="description">` stay exactly as they are; `og:title` and `og:description` repeat them. `og:site_name` is `РЭХА`, `og:type` `website`, `twitter:card` `summary_large_image`, `og:image:alt` "РЭХА: the rehearsal screen, playing a take" (first written as "…with four tracks of a take"; the picture shows three, Vocals is below its edge).
- Picture layout as in mockup variant 2: the page's tile grey; on the left the app's icon and "РЭХА", the hero's title (`site/content/hero.md` `#`) and its eyebrow in the page's red; on the right the hero scene of `stage.html` (`#hero`), going off the right and bottom edges with the site's screen shadow and radius.
- 404 as in mockup variant 2: the site's menu (links go to `/#how`, `/#faq`, `/`) and footer; "404" as the eyebrow; heading and line from a new `site/content/notfound.md`; a "Go to the main page" button to `/` and the download link for the visitor's system as the hero picks it; beside it (under it on a phone) the app's `SongTab` and `TakePlayer` for Take 404, flat on Drums, Bass, Guitar and Vocals, inert like the tiles' pieces.
- Status 404 for every address that is not a file; `/mac` and `/windows` keep answering 307 first.
- `robots.txt` lets every crawler in, AI ones included, and names the sitemap; `stage.html`, `og.html` and `404.html` carry `<meta name="robots" content="noindex">`. The sitemap lists `https://reha.stream/` only.
- JSON-LD: `SoftwareApplication`, name `РЭХА`, `alternateName` `Rehearsal Recorder`, the build's version, macOS and Windows, free, MIT, the two zips as `downloadUrl`.
- Analytics stays on `index.html` only: the 404 page and `og.html` do not call `inject()`.
- No new dependencies. Comments say why, in plain sentences, like the code around them. Test titles in Latin script.
- Checks: `cd site && npm test`, `npx tsc -b`, `npm run build && npm run og && npm run test:e2e`.
- Commits end with the session's attribution lines.

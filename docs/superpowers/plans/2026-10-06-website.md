# The website: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A landing page at reha.stream, built in `site/` from the app's own
components on the fake bridge, tested on every pull request and deployed to
Vercel when a release is out.

**Architecture:** `site/` is a Vite + React project that imports `ui/src`
through the `@/` alias and uses the interface's own React. The page renders
small prop-only components in place (the tiles); the hero and the story are
frames of `stage.html`, each a window with its own fake bridge, driven by
`postMessage`. Text comes from `site/content/*.md` and `CHANGELOG.md` at
build time.

**Tech stack:** Vite 8, React 19, TypeScript 7, Tailwind 4 (for the app's
CSS), Vitest 5, Playwright 1.63, GitHub Actions, Vercel CLI.

**Spec:** [docs/superpowers/specs/2026-10-06-website-design.md](../specs/2026-10-06-website-design.md)

**Design reference:** the approved preview,
<https://claude.ai/artifact/5TcydAK3GtgECuiZsQXfMB>. Its `index.html` holds
the page's CSS and markup; its `app/demo-bridge.js` ends with the director
(timers held off screen, 24 frames a second, the guitar's clips, the
synthetic drag). Read them with the Artifact tool's `read`.

## Global constraints

- Node 22. The site's tool versions are the interface's:
  `vite ^8.3.2`, `@vitejs/plugin-react ^6.1.1`, `@tailwindcss/vite ^4.3.3`,
  `tailwindcss ^4.3.3`, `typescript ~7.0.2`, `vitest ^5.0.3`,
  `@playwright/test ^1.63.0`, `@types/node ^26.6.4`.
- One React: `react` and `react-dom` (and their types) resolve to
  `ui/node_modules` for every file, the site's included. The site's
  `package.json` does not list them. CI runs `npm ci` in `ui/` before `site/`.
- Nothing in `ui/src` changes except Task 2.
- The page is light only. The app inside it is in its light theme.
- A frame lays the app out at **1180 × 960** and scales it to the frame's
  width.
- Phones: under **720 px** the tiles stack, the wide piece shows its left
  part at **560 px**, and the frames are not interactive.
- A frame off screen holds; a frame on screen runs at most **24** animation
  frames a second.
- Downloads:
  `https://github.com/voronizer/rehearsal-recorder/releases/latest/download/RehearsalRecorder-macos.zip`
  and `…/RehearsalRecorder-windows.zip`.
- Release notes: `https://github.com/voronizer/rehearsal-recorder/releases/tag/<tag>`.
  Tags are bare versions (`0.9.0`); a leading `v` is dropped for display.
- Commit subjects are plain sentences, as in `git log`.

## Review focus

1. **A release tag with a leading `v`** (`v1.0.0`, as `release.yml`'s own
   comment suggests): the page shows `1.0.0`, the link keeps the tag.
   Pinned in Task 3.
2. **A version with no `CHANGELOG.md` section, or a section with no bold
   lead:** the news line is *New in 1.0.0.* with the link, and the build
   does not fail. Pinned in Task 3.
3. **Content edited so a tile or step id is missing or misspelt:** `npm
   test` fails, naming the file and the id, rather than a tile going blank
   on the live site. Pinned in Task 3.
4. **A jump straight from step 1 to step 4** (the rail, or a fast scroll):
   the story frame ends on History, not on whichever scene finished
   setting up last. Pinned in Task 4.
5. **A Windows visitor:** the Windows zip is the button. Pinned in Task 5.

**Files:**

**Interfaces:**
- Produces, `frame.ts`:
  `type ToStage = { type: "rr-step"; step: number } | { type: "rr-hold"; hold: boolean }`
  and `type FromStage = { type: "rr-ready" }`. The stage sets
  `document.documentElement.dataset.scene` (`hero`, or a step id) once a
  scene is fully set up, and `dataset.held` to `"true"`/`"false"`.
- Produces, `hold.ts`: `createHold(win: HoldWindow, fps = 24): { hold(on: boolean): void; held(): boolean }`,
  where `HoldWindow` is the subset of `Window` it replaces:
  `setTimeout`, `clearTimeout`, `setInterval`, `requestAnimationFrame`,
  `cancelAnimationFrame`. Held: timeouts and frames wait and run on
  release, intervals skip their ticks. Running: frames are at least
  `1000 / fps` ms apart, all callbacks of one frame run together, and
  `cancelAnimationFrame` cancels a frame however many times it was
  deferred. The preview's director has a working version of this.
- Produces, `demo.ts`: `installDemo(): void` — runs `ui/e2e/fake-bridge.js`
  and `ui/e2e/band.js` (imported `?raw`) as one classic `<script>`, then on
  the bridge: settings say `theme: "light"`, `ui_scale: 1`;
  `save_appearance` does nothing; `fetch` of `/api/…` answers 404 without a
  request; `setPointerCapture`/`releasePointerCapture` never throw;
  `focus()` never scrolls; `scrollIntoView` does nothing inside a frame;
  `get_levels` reports the guitar at full scale for 0.2 s at 1.2, 2.2 and
  3.4 s after `start_take`, so the take ends with *clipped 3×*.
- Produces, `drive.ts`: `waitFor`, `press(text, {exact})` (matching a
  button's words without its key hint), `dragTimeline(from, to)` — the
  preview director's helpers, typed.
- Produces: `stage.html#hero` and `stage.html#story`.

# Folding a track's notes in the player: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every lane of notes in the player opens folded to a strip, with a
chevron after its M that opens it, and the grey moves from under the
pictures to the plates.

**Architecture:** All of it is in the shared player (`ui/src/components/Timeline.tsx`
and the plates beside its lanes), so РЭХА's rehearsal screen, History and
the band service's take page change together. Timeline keeps which lanes of
notes are open; NotesPlate draws the arrow and the MIDI sign; the grey is a
layer behind each plate, so a plate's box keeps the row's height.

**Tech Stack:** React 19, Tailwind 4 (`cn` = clsx + tailwind-merge), Playwright
e2e in `ui/`, `service/`, `site/`; Python Playwright for the guide pictures.

**Spec:** `docs/superpowers/specs/2026-11-10-midi-fold-design.md` (Alex's
«ок» 2026-11-10 13:21Z). The mockup's ui diff, a starting point only:
`/mnt/project-files/band-service/midi-fold/q1-mock/ui-b-dashed.diff`.

- While developing, run only the tests a change touches, once each; the full
  suites run once, on CI. Say so in every subagent brief.
- Local browser tests: `@playwright/test` wants a Chromium the container
  lacks; use a throwaway config with `launchOptions.executablePath:
  "/opt/pw-browsers/chromium"`, never committed. Same for
  `tests/docs_screenshots.py` (`executable_path`).
- Test titles and check labels: cp1252 characters only (Windows CI).
- Words people read follow CLAUDE.md "Writing": British spelling, curly
  double quotes in the guide, README and CHANGELOG, button names in bold,
  each CHANGELOG item starting bold. Check the guide and CHANGELOG text with
  the humanizer skill.
- Rows keep their heights: a track's and Master's 56 px (`LANE_REM` 3.5), an
  open notes row 94 px under its track and 96 px alone (NotesPlate's
  `MIN_HEIGHT`, unchanged).
- Folded strip rows: `calc(1.5rem + 3px)` under a track (notes 24 px),
  `calc(1.5rem + 8px)` alone (notes 26 px).
- The grey: `bg-well`, 1 px in from the row's top and bottom except where a
  track and its notes join, over the 12 px column gap to the picture's left
  edge, left corners `rounded-md` (8 px), right ones square.
- No code before Alex says this may run beside the thread «Сделать понятными
  переходы в сервисе» (or that thread has merged). Both touch CHANGELOG and
  may touch `service/e2e/takes.spec.ts` and the `downloads` picture:
  whichever merges second rebases and retakes.

## Review Focus

1. Zooming, scrolling or playing must not fold a lane the band opened: the
   open set empties only when the player has no tracks (a take closing or
   opening), and zoom refetches peaks without emptying them. Test in Task 2.
2. ↑/↓ to the next take, or another take opened from the list, folds every
   lane again. Test in Task 2.
3. Space on the arrow, reached with Tab, opens it and does not start the
   take (useSpacebar presses a keyboard-focused button). Test in Task 2.
4. A lane whose port never appeared still says “No notes in this take” when
   folded. Test in Task 2.
5. A MIDI-only track with a long name, folded, at 960 px: name cut, MIDI
   sign, M and arrow all on the line, nothing outside the plate. Test in
   Task 2.
